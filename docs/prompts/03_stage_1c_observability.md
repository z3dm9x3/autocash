# Этап 1c. Трассировка, команды отладки, эксплуатация и приёмка ядра

> Контекст — `CLAUDE.md`. Уже готовы конвейер (1a) и пул (1b). Этот промт завершает этап 1 «Ядро» и включает его итоговые критерии приёмки.

## Цель

По любой задаче видно, где она сейчас, сколько провела на каждом этапе и чем закончилась. Оператор управляет системой командами. Жёсткая перезагрузка сервера под нагрузкой не теряет ни одного подтверждённого события и не отправляет ничего дважды.

## Что сделать

### 1. Полная трассировка (ФТ-11.1–11.4, 11.6, 11.11)
- Два вида задач: входящая и исходящая. Исходящая хранит trace_id породившей входящей, правило и его версию.
- Этапы исходящей: создана → в очереди Вывода → назначен аккаунт → отправка → доставлено (msg_id). Каждая попытка отправки — отдельная строка: аккаунт, время, результат, код ошибки Telegram.
- Статусы: «в работе»; «ожидает» (код причины + время, до которого ждёт); финальные — доставлено, обработано, пропущено, не доставлено, истёк срок, отменено, симуляция. Все финальные, кроме «доставлено» и «обработано», имеют код причины.
- Хранение: одна строка на входящую задачу с отметками этапов, строка на каждую обработку модулем, строка на исходящую задачу и на каждую попытку. Детальные трассы хранятся N дней (конфиг), агрегаты — бессрочно.
- После рестарта незавершённые задачи продолжаются с последнего зафиксированного этапа.

### 2. Справочник кодов причин (ФТ-11.5)
Таблица в БД и enum в коде:

| Код | Значение | Статус |
|---|---|---|
| FLOOD_WAIT | аккаунт/метод на паузе до T | ожидает |
| ACCOUNT_PAUSED | нужный аккаунт paused или disconnected | ожидает |
| NO_ACCOUNT_IN_CHAT | в чате нет активного аккаунта пула | ожидает |
| DB_UNAVAILABLE | PostgreSQL недоступен | ожидает |
| ACCOUNT_RESTRICTED | PEER_FLOOD | ожидает / не доставлено |
| ACCOUNT_LOST | бан или отзыв сессии | ожидает / не доставлено |
| CHAT_DELETED | чат удалён / аккаунт исключён | не доставлено |
| CHAT_WRITE_FORBIDDEN | нет права писать | не доставлено |
| USER_IS_BLOCKED | клиент заблокировал аккаунт | не доставлено |
| TTL_EXPIRED | истёк срок жизни | истёк срок |
| MODULE_ERROR, MODULE_TIMEOUT | ошибка или таймаут модуля | ожидает перезапуска |
| UNKNOWN_TYPE | нет подходящего правила | пропущено |
| ACCESS_DENIED | недостаточно прав (поправка к ТЗ) | отменено |

Новый код ошибки Telegram сохраняется как есть и попадает в сводку для пополнения справочника.

### 3. Зависание и метрики (ФТ-11.7, 11.10)
- Норматив времени на каждый этап (конфиг). Превышение → отметка «зависла» и попадание в `/stuck`. Массовое зависание на одном этапе (порог в конфиге) → тревога с названием этапа.
- Метрики по этапам: медиана и p95 длительности, число задач на этапе, распределение финалов по кодам причин; срезы по источнику, модулю и аккаунту.

### 4. Команды, роли, права — базовый уровень (ФТ-11.9, 12.1, 12.2, 12.4, 12.6, 12.7)
- Роли пользователей: player, casher, manager, admin, support, dev. У пользователя может быть несколько ролей; роль глобальная или привязанная к источнику. Списки расширяются конфигом.
- Матрица прав «роль пользователя × роль источника → команды». Недостаточно прав → отказ, финал «отменено» с `ACCESS_DENIED`.
- Каждая команда — задача с трассой: автор, источник, аргументы, результат.
- Команды:

| Команда | Результат |
|---|---|
| `/trace <trace_id \| Deposit ID \| ссылка на сообщение>` | все этапы задачи и связанных задач с длительностями, попытки, коды причин |
| `/stuck [этап]` | зависшие, сгруппированные по этапу и коду |
| `/retry <trace_id \| фильтр>` | перезапуск с текущего этапа |
| `/cancel <trace_id \| фильтр>` | отмена с записью автора |
| `/queue` | длины очередей модулей и Вывода по аккаунтам |
| `/accounts` | пул: состояние, паузы, остаток бюджета, обязанности |
| `/coverage` | недопокрытые чаты и чаты с приблизительной дедупликацией |
| `/status` | сводка по всему перечисленному + время до полной готовности после старта |
| `/reload` (или аналог) | перезагрузка конфига (ФТ-13.3) |

- Поиск по Deposit ID в `/trace` сделай через расширяемый резолвер: модуль «Заявки» подключит его на этапе 2.
- Команды чтения отвечают из агрегатов в памяти и индексированных таблиц за ≤ 1 с. Для тяжёлого отчёта — мгновенное подтверждение и результат по готовности.

### 5. Эксплуатация (НФТ-14–18)
- **Аварийный канал**: `/status`, `/accounts` и тревоги обслуживает Gateway напрямую, они работают при недоступном PG.
- **Watchdog**: сигнал жизни из основного цикла (`sd_notify`, `WatchdogSec`). Зависший процесс перезапускается. Приложи systemd-unit.
- **Старт**: приём в SQLite начинается сразу после запуска; время до полной готовности измеряется и показывается в `/status`.
- **Отчёты**: отдельный пул соединений со `statement_timeout`, только по заранее рассчитанным агрегатам; задержка записи пачек остаётся в норме.
- **Бэкапы**: скрипты периодического дампа PG и архивации WAL на другой носитель плюс скрипт проверки восстановления. Опиши в `docs/ops.md`.

### 6. Поведение после жёсткой перезагрузки (п. 3.4) — проверить и закрыть пробелы

| Компонент | Ожидаемое восстановление |
|---|---|
| События за время простоя | догон по чатам с разрывом через лимитер; «difference too long» → сверка |
| SQLite | подтверждённое цело, Uploader продолжает |
| Пачка Uploader | выгружается повторно, upsert даёт тот же результат |
| Очереди, горячие данные | пересборка из PG от отметок модулей, приём новых событий начинается сразу |
| Исходящее «отправка» | повтор с тем же random_id, дубль отклоняется |
| Паузы FloodWait | из БД, лимитер продолжает паузы |
| Состояния диалогов | из БД как есть |
| Трассы | продолжение с последнего этапа |
| Пул | аккаунты подключаются независимо, планировщик распределяет по мере готовности |
| Зависший процесс | watchdog перезапускает |

## Итоговые критерии приёмки этапа 1 (из ТЗ, каждый — автотест; где нужно — сценарий в `docs/acceptance/stage1.md`)
1. Сообщения из источников `full` попадают в PG и получают тип в пределах НФТ-6 (≤ 1 с).
2. Жёсткий сброс под нагрузкой (kill -9 в случайные моменты, серия прогонов): все подтверждённые события обработаны; каждая исходящая задача доставлена ровно один раз или имеет финальный статус с причиной.
3. Догон 100 чатов — без FloodWait.
4. Изменение пула 3 → 1 и 1 → 10 во время работы отражается в `/accounts` и `/coverage` за N секунд.
5. Блокировка аккаунта и удаление чата видны в `/trace` затронутых задач с кодом причины.
6. `/status` и `/accounts` отвечают при остановленном PostgreSQL.
7. Зависание на этапе выше порога → тревога с названием этапа.
8. Команда без прав → `ACCESS_DENIED`, запись в трассе.
