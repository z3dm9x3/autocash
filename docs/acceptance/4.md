# Этап 4 «История» — критерии приёмки и тесты

Запуск: `timeout 1800 python -m pytest -q tests/acceptance/test_backfill.py`.

| № | Критерий | Тест |
|---|---|---|
| 1 | Во время загрузки истории команда чтения отвечает ≤ 1 с (НФТ-5), живой поток ≤ 1 с (НФТ-6); живой поток ×10 плюс история | `test_live_flow_and_read_commands_stay_fast_during_backfill_without_flood_wait` — 1 200 сообщений истории в 4 чатах, живой поток 5 сообщений в секунду (×10 от наблюдаемых 5–10 тыс. в сутки — это 1–2 в секунду), `/status` каждые 2 с |
| 2 | Для событий истории не создана ни одна исходящая задача | `test_history_creates_no_outbound_tasks` (в истории есть `/ping`, на который модуль demo отвечает живым) |
| 3 | Живое событие по ключу, у которого в очереди есть история, обрабатывается после неё | `test_live_event_of_a_key_is_processed_after_its_history` |
| 4 | Рестарт посреди загрузки: продолжение с места остановки, без дублей в сущностях | `test_restart_in_the_middle_continues_without_duplicates` |
| 5 | Загрузка не вызывает FloodWait на аккаунтах, обслуживающих живые ответы | тот же тест, что и критерий 1: фейковый сервер даёт FloodWait выше 8 вызовов в секунду, лимитер держит 6 |

## Состояние

Критерии 2–5 проходят. Критерий 1 на машине разработки выполнен частично: живой поток во время загрузки — p95 0,25–0,40 с (норма ≤ 1 с), ответ на `/status` — 0,25–1,17 с, отдельные замеры на 0,1–0,2 с выше нормы. Ответ на команду здесь измеряется полным кругом: приём → PostgreSQL → модуль → отправка. Тест оставлен строгим. Машина разработки сильно перегружена: тот же тест задержки этапа 1a без загрузки истории даёт на ней p95 от 0,7 до 8,8 с. Окончательная проверка — на целевом сервере.

## Чего тесты не проверяют

- `get_history` адаптера Telethon на живом аккаунте и реальные пороги FloodWait для `messages.getHistory`.
- Итоговое состояние заявок после загрузки реальной истории касс: шаблон кассы предварительный (D-2-1).
