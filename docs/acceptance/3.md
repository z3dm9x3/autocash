# Этап 3 «Реакции» — критерии приёмки и тесты

Запуск: `timeout 1800 python -m pytest -q tests/acceptance/test_reactions.py`.

| № | Критерий | Тест |
|---|---|---|
| 1 | Правило включается, выключается и меняется через конфиг без рестарта; невалидное правило не применяется, ошибка уходит в `logs` | `test_rule_is_switched_and_changed_by_config_without_restart`, `test_rule_config_errors_are_reported_at_load` |
| 2 | Dry-run создаёт только задачи «симуляция» и записи журнала; прогон по истории даёт отчёт | `test_dry_run_creates_only_simulations_and_the_journal` |
| 3 | Автоответ не отправляется, если сотрудник писал в диалог за последние N минут | `test_autoreply_waits_while_a_staff_member_talks_and_obeys_the_limit` (также лимит ответов на диалог) |
| 4 | Каждая исходящая задача доходит до финального статуса | `test_scam_unban_rights_marks_and_clarification` (проверка в конце), `test_timer_fires_later_and_external_actions_are_final` |
| 5 | `kill -9` между записью состояния диалога и отправкой: ответ уходит ровно один раз | `test_kill_9_between_dialog_state_and_send_answers_exactly_once` (две точки: после коммита и перед отправкой) |
| 6 | `scam` / `unban` без прав → `ACCESS_DENIED`; с правами → запись в санкциях с автором | `test_scam_unban_rights_marks_and_clarification` |
| 7 | Неоднозначный идентификатор без префикса → уточняющий вопрос, после ответа команда выполняется | `test_scam_unban_rights_marks_and_clarification` |

## Чего тесты не проверяют

- Реальные пороги спам-ограничений Telegram для пользовательских аккаунтов: лимиты автоответов — оценка (OPEN-QUESTION, `docs/open_questions.md`).
- Правила на реальных текстах касс: шаблон кассы предварительный (этап 2, D-2-1).
