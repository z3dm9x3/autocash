# Кассы и кассиры — база знаний

Справочник касс: какие группы относятся к кассе, кто её кассиры (TGID, username), какими номерами методов она управляет, какие реквизиты выдаёт. Для людей и агентов. Термины — как в `AGENTS.md` Autocash; заявки — `deposits.md`, выводы — `withdrawals.md`.

- Часть II. Справочник: §6 Кассы · §7 Особенности касс · §8 Группы без WW · §9 Полигон
- Часть III. §10 Служебные аккаунты · §11 Нагрузка и часы работы · §12 Источники и обновление

# Часть I. Правила

## 1. Термины

| Термин | Значение |
|---|---|
| **Касса** | Платёжный сервис, который принимает депозиты и выплачивает выводы игроков. Имеет свою WW-группу и одну или несколько DOP-групп. |
| **DOP-группа** | Группа депозитов кассы: карточки `[ДЕПОЗИТ …]`, реквизиты, чеки (`deposits.md`). |
| **WW-группа** | Группа выводов кассы: карточки `[ВЫВОД]` (`withdrawals.md`). |
| **Кассир** | Аккаунт, который выдаёт реквизиты на заявки (§3). У кассы может быть несколько кассиров; один кассир может работать на нескольких кассах. |
| **Метод** | Способ оплаты кассы с названием и лимитами (`Метод оплаты:` в карточке). |
| **Номер метода** | Сквозной номер метода на платформе, аргумент команд `/turn_on N`, `/turn_off N`, `/change_dep_limits N` (§4). |
| **Платформа** | Номер кассы в карточке `[ВЫВОД]` (`Платформа: N`). Один на кассу. |

## 2. Касса: идентичность и название

**Правило: одна WW-группа — одна касса.** Касса определяется своей WW-группой, независимо от числа DOP-групп и методов. Всё, у чего общая WW-группа, — одна касса с одними кассирами.

**Название кассы — по названию группы, а не метода.** Из названия группы убираются служебные слова: `DOP`, `Dop`, `(DOP)`, `WW`, `Withdraw`, `Выводы`, `CASH`/`Cash`, `Kassa`, `reserv`/`Reserv`, `night`, номер группы (`-2`, `-3`), `Preset-N`. Варианты групп одной кассы сводятся к ней: `Favorit-3 DOP`, `Favorit night dop`, `Favorit Cash DOP` → **Favorit**; `Blade reserv` → **Blade**; `Pay T (reserv) DOP` → **Paytronix**.

Исключения:
- **Queen Cash = Amun Pay = Fast Cash.** Одна касса: DOP-группы `Queen Cash DOP`, `Amun Pay DOP`, `Fast Cash DOP`, общая WW-группа `Queen Cash WW` и общие кассиры. Отдельной WW-группы у Amun Pay и Fast Cash нет.
- **Pulpy и Premier — две кассы с одним кассиром** (`@angel_melbet`). WW-группы разные (`Выводы Pulpy`, `Premier Withdraw`), номера методов обеих касс включаются в обеих DOP-группах (§4).
- **HEETSPAY** работает и под названием метода `REGINCASH SERVICE` — в отдельной DOP-группе с кассиром `@heetspay1` (§7).
- **Hermes** — также `Ghost Cash DOP`: методы `Ghost Pay` (356) и `Hermes Cash СБП` (357), команды даёт кассир Hermes (§7).

Названия методов не определяют кассу: касса меняет названия и пишет их в разных форматах (`Gogen СБП` → `[Карты] | 1 500 - 1 500 | Gogen`); у Falcone в названии опечатка `Falocne`.

## 3. Кассир

**Кассир — отправитель сообщения с реквизитом, на которое бот платформы (`7185799444`) ответил «Реквизиты успешно отправлены пользователю ID <TGID>».** Это единственный признак, одинаковый для всех касс с ручной выдачей.

- Кассир также включает и выключает методы (§4) и в WW-группе отвечает на карточки `[ВЫВОД]` («Готово», «Остаток N»).
- Методами иногда управляет аккаунт кассы, который сам реквизиты не выдаёт: `@blade_trust` у Blade, `@AlexandrHamilton` у Top Pay.
- **Выдача без кассира:** Top Pay — интеграция, реквизит пишет сам бот платформы (`✅ Реквизиты выданы`, `deposits.md` §14); Предустановленная сумма — бот выдаёт реквизит в карточке (`deposits.md` §13).
- **Полигон** — реквизиты выдают магазины, десятки аккаунтов (§9).
- **Не кассиры:** поддержка RUCASH, бот проверки чеков AIKassir, аккаунт монитора, технический аккаунт (§10). Они тоже пишут в DOP- и WW-группах.

Username берётся из `raw_payload->>'sender_username'` последнего сообщения аккаунта. Если поле пустое, в таблице §6 указан контакт, который кассир ставит подписью в своих реквизитах (`подпись @…`). Это не обязательно username самого аккаунта.

## 4. Номера методов

- Номер метода сквозной по всей платформе: один номер — один метод одной кассы.
- Команды кассира в DOP-группе и ответы бота:

  | Команда | Ответ бота |
  |---|---|
  | `/turn_on N` | `Метод оплаты <название> <min> - <max> успешно включен.` |
  | `/turn_off N` | `✅ Метод оплаты <название> <min> - <max> успешно выключен.` + иногда блок `📊 Перенаправление депозитов: • Всего обработано: N • Перенаправлено: N • Не удалось: N` |
  | `/change_dep_limits N` | `Введите новый нижний лимит (min_value) или '-' для пропуска:` (диалог лимитов) |
  | ошибочный формат | `Неверный формат. Используйте: /change_dep_limits <ID метода>` |
  | аккаунт без кассы | `У вас не привязана касса.` |

- Номер и метод связываются по ответу бота с названием метода на ближайшую предыдущую команду в той же группе.
- Название метода по одному номеру меняется со временем: `Hermes Cash СБП` ↔ `Hermes Cash СБП/Карты` (357), `[PDF] СБП 🌙` → `[PDF] СБП 📱` (353). В §6 указано основное название.
- Номера в командах бывают ошибочными (`/turn_on 3456`, `/change_dep_limits 8579016673563`): бот не подтверждает, такие номера в справочник не вносятся. Без подтверждения бота номер указан в §7 как «неподтверждённый».
- Администраторы используют варианты `/turn_on_dp`, `/turn_off_dp`, `/turn_on_wd` (депозитные и выводные методы) в служебных группах.

## 5. Типы реквизитов

Тип определяется по сообщению кассира с реквизитом (на которое ответил бот, §3):

| Тип | Как выглядит | Признак |
|---|---|---|
| **СБП** | телефон и банк: `+79XXXXXXXXX\nСбербанк` | 11 цифр, начало `7`/`8`, затем `9` |
| **Карта (P2P)** | номер карты и банк: `2202 20XX XXXX XXXX\nТ-Банк` | 16–19 цифр |
| **Счёт** | 20 цифр | редко (Hermes) |
| **QR-ссылка СБП** | `https://qr.nspk.ru/…` + «Оплата по ссылке и чек пдф!» | ссылка `qr.nspk.ru` |
| **Платёжная ссылка** | `https://merchant.tamtut.app/pay/…`, `https://gate.fabel.cc/payment/…` | ссылка на платёжную страницу |
| **Интеграция** | бот: `✅ Реквизиты выданы\n💳 <Банк> •••• NNNN` | только Top Pay |

Дополнительные строки в реквизите:
- банк, иногда ФИО получателя (Trust Cash, Полигон);
- точная сумма: `Переведите точную сумму 500₽ !` (Fast Cash), сумма третьей строкой (Hermes: `\nт банк\n560`, Falcone: `\nТ-Банк\n2000`);
- подпись-контакт и правило по чеку: `@Monetra_Sup`, `❗️15 минут на оплату и ПДФ чек`, `❗ На прикрепление чека отводится 15 минут`, `❌НЕ ПРИНИМАЕМ❌переводы — с СБЕР КИДС, ИП, МТС Банка, QPlus…`.

**Фиктивный реквизит** — нули или единицы вместо номера и указание игроку: `00000000\nОтмена`, `00000000\nНа 5000`, `00000000\nПриделайте на 1995`, `00000000000\nПересоздайте заявку на другую платформу, или измените сумму на 3.000₽`, `00000000000\nПересоздайте заявку методом QR`, `111111111\nотмените пожалуйста`, `10202772736\nРеквизиты уже забрали,пересоздайте заявку`. Так кассир отказывает по заявке через кнопку выдачи. Это не реквизит для оплаты.

## 12. Источники и обновление

Монитор, PG 5433, БД `rucash`, только чтение:

```sql
-- кассиры: кто выдал реквизит (бот ответил «Реквизиты успешно отправлены»)
select r.title, a.sender_id, max(a.raw_payload->>'sender_username') as username, count(*)
from raw_messages b
join raw_messages a on a.chat_id = b.chat_id and a.telegram_account_id = b.telegram_account_id
                   and a.telegram_message_id = b.reply_to_message_id
join chat_registry r on r.chat_id = a.chat_id and r.telegram_account_id = a.telegram_account_id
where b.sender_id = 7185799444 and b.text like 'Реквизиты успешно отправлены%'
group by 1, 2 order by 1, 4 desc;

-- номера методов в группе
select chat_id, substring(text from '^/(?:turn_on|turn_off|change_dep_limits)\s*(\d+)') as method_no, count(*)
from raw_messages where text ~ '^/(turn_on|turn_off|change_dep_limits)' group by 1, 2;

-- название метода: ответ бота
select chat_id, message_date, text from raw_messages
where sender_id = 7185799444 and text ~ 'Метод оплаты .* успешно (включен|выключен)';
```

- `raw_payload->>'sender_username'` заполнен не у всех сообщений; брать последнее непустое по аккаунту.
- Группы без названия в `chat_registry` (`-1004479515951`, `-1004450405945`, `-1004436739036`, `-5241452952`, `-1004372047251`) опознаны по методам и кассирам; их названия в Telegram стоит внести в реестр.
- В мониторе есть справочник касс WW Helper: `ww_helper_cashdesks` (около 100 касс, город, у части — номер метода в `cash_number`) и `ww_helper_cashdesk_aliases`.
- В Autocash роль группы задаётся в Role Manager: `/rm set <chat_id> dop|ww`.

Как пополнять:
- **Новая касса** — строка в §6. Касса новая, только если у неё своя WW-группа (§2).
- **Новая DOP-группа** — добавить в строку кассы по кассиру и номерам методов.
- **Новый кассир** — TGID, username, группы. Признак кассира — §3.
- **Новый номер метода** — только после ответа бота «успешно включен/выключен».
