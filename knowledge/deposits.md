# Заявки на депозит — база знаний

Единый справочник: как выглядят, проходят и связываются заявки на депозит в DOP-группах касс. Для людей и агентов. Термины — как в `AGENTS.md` Autocash.

- Часть II. Методы: §12 Треугольник · §13 Предустановленная сумма · §14 Top Pay · §15 Полигон · §16 NSPK (СБП QR-линк)

# Часть I. Общее

Заявка на депозит — запрос игрока пополнить игровой счёт через кассу. Касса работает в своей DOP-группе Telegram. Все карточки заявок в DOP-группах публикует и редактирует **бот кассовой платформы** (один и тот же бот во всех группах, TGID `7185799444`). Остальные участники: кассиры кассы, администраторы платформы, у Полигона — бот-координатор.

Специфика методов — в части II (§12–§16). Здесь — то, что верно для всех.

## 1. Опознание по первой строке

Первая строка сообщения бота — заголовок в квадратных скобках.

| Заголовок | Смысл | Тип сортировщика |
|---|---|---|
| `[ДЕПОЗИТ ТРЕУГОЛЬНИК]` | Создана заявка, касса должна выдать реквизит | `deposit.request` |
| `[ДЕПОЗИТ ПРЕДУСТАНОВЛЕННАЯ СУММА]` | Создана заявка, реквизит выдан ботом сразу в карточке | `deposit.request` |
| `[ДЕПОЗИТ ПОЛИГОН]` (без `Пользователь:`, с `Оператор, выдайте реквизиты!`) | Создана заявка метода Полигон | `deposit.request` |
| `[ДЕПОЗИТ ПОЛИГОН]` (с вложением и итогом) | Чек по заявке Полигона | `deposit.receipt` |
| `[ДЕПОЗИТ NSPK (СБП QR-ЛИНК)]` | Создана заявка, касса должна выдать QR-ссылку СБП | `deposit.request` |
| `[ДЕПОЗИТ]` | Игрок прислал чек об оплате | `deposit.receipt` |
| `[ВЫВОД]` | Заявка на вывод, к депозитам не относится | — |

Суффикс ` 🔄 ПЕРЕНАПРАВЛЕН` после заголовка (`[ДЕПОЗИТ ТРЕУГОЛЬНИК] 🔄 ПЕРЕНАПРАВЛЕН`, `[ДЕПОЗИТ ПОЛИГОН] 🔄 ПЕРЕНАПРАВЛЕН`) — заявку перенесли сюда из другой кассы (§6). Deposit ID сохраняется.

Доли сообщений с заголовком за 14 дней по всем DOP-группам (≈ 77 тыс.): ТРЕУГОЛЬНИК ≈ 66 %, `[ДЕПОЗИТ]` ≈ 27 %, с суффиксом ПЕРЕНАПРАВЛЕН ≈ 2,8 %, ПОЛИГОН ≈ 2,2 %, ПРЕДУСТАНОВЛЕННАЯ СУММА ≈ 1,8 %, NSPK < 0,1 %.

## 2. Поля карточки

Карточка — набор строк `Ключ: значение` после заголовка.

| Строка | Поле Autocash | Формат и замечания |
|---|---|---|
| `Deposit ID: 1477606` | `deposit_id` | Целое, сквозное по всем кассам. Ключ заявки. |
| `Пользователь: <имя или @username> ID: <TGID>` | `tgid` (+ имя в `player_names`) | Имя — отображаемое имя Telegram либо `@username`, может быть любым текстом (`…`, `......`). TGID — число после последнего `ID: `. |
| `ID: <TGID>` | `tgid` | В карточках Полигона вместо строки `Пользователь:`. |
| `Тип пользователя: USER` | — | Значения: `USER`, `TRUSTED`, `NEW`. |
| `Успешных депозитов: 🔴 604 (всего: 635)` | — | Цветная метка и счётчики игрока (§2.1). |
| `Номер счёта: 352533335` | `mel_id` | MelID. Целое без разделителей. |
| `Сумма пополнения: 36000.00` | `amount` | В заявке — запрошенная сумма, точка, без разделителя тысяч. В `[ДЕПОЗИТ]` — с пробелом тысяч: `10 000.70` (§5). |
| `Накопленный бонус: 0.62` | — | Есть не всегда; копеечный бонус игрока. |
| `Метод оплаты: <название> <min> - <max>` | `method` | Платёжный метод кассы с текущими лимитами (§2.2). |
| `Оператор, выдайте реквизиты!` | — | Призыв к кассе выдать реквизит. У NSPK: `Оператор, выдайте QR-ссылку СБП!` |

После полей идут блоки, которые бот дописывает правкой (этап, отмена, перенаправление).

### 2.1 «Успешных депозитов»

- В карточке заявки: `<метка> N (всего: M)`; в карточке `[ДЕПОЗИТ]` и в части карточек Полигона/Предустановленной суммы: `<метка> N`.
- Метки: 🟢 🟡 🟠 🔴. Наблюдаемые диапазоны N: 🟢 0–4, 🟡/🟠 5–9, 🔴 ≥ 11. **[трактовка]** Метка — уровень опыта игрока по числу успешных депозитов, N — успешные, M — все созданные. Правило окраски точно не выведено (встречаются 🟡 6 и 🟠 6).
- Большие числа с пробелом тысяч: `🔴 1 074 (всего: 1 167)`.

### 2.2 «Метод оплаты»

- Формат свободный, задаётся кассой: `[СБП] [Карты] BLADE [PDF] 3 000 - 500 000`, `Конкретная сумма SprintPay 500 - 100 000`, `Top Pay 1 000`, `Полигон Моментальный ⬡  1 000 - 3 000`, `Hermes Cash 2 СБП/Карты 950 - 950`, `[PDF] QR-КОД 📱 | 10 000 - 100 000`.
- Хвост `<min> - <max>` — **текущие** лимиты метода на момент публикации или правки карточки. Касса меняет их в течение дня (`/change_dep_limits`), поэтому у одной заявки в карточке запроса и в `[ДЕПОЗИТ]` лимиты могут отличаться: `…BLADE [PDF] 3 000 - 500 000` → `…BLADE [PDF] 5 000 - 500 000`; `Hermes Cash СБП/Карты 470 - 470` → `Hermes Cash СБП/Карты 1 003 - 1 003`. Метод идентифицируется по названию без хвоста лимитов (так хранит `payment_methods.name`).
- Метки в названии — договорённости кассы: `[PDF]`/`[ТОЛЬКО ЧЕК PDF]` — чек принимается только PDF; `[Без SberKids]`; `Reserv` — резервный метод.
- Метод с `min = max` — фиксированная сумма (Hermes, Top Pay `Top Pay 500`).
- В названиях платформ бывают невидимые символы U+2060 (WORD JOINER) в начале: `⁠⁠⁠…Pay T 🟠`. Нормализовать перед сравнением.

## 3. Жизненный цикл

```
created ──► requisites ──► sent ──► receipt ──► final (success | rejected)
   │             │           │          │
   └─────────────┴───────────┴──────────┴──► cancelled
```

| Этап `deposits.stage` | Что видно в группе | Тип |
|---|---|---|
| `created` | Бот публикует карточку заявки (§1) | `deposit.request` |
| `requisites` | Касса выдаёт реквизит: ответ кассира на карточку / авто-выдача ботом / интеграция (по методу) | `deposit.requisites` |
| `sent` | Бот подтверждает отправку реквизита игроку: «Реквизиты успешно отправлены пользователю ID <TGID>» | `deposit.sent` |
| `receipt` | Бот публикует **новую** карточку `[ДЕПОЗИТ]` с вложением чека | `deposit.receipt` |
| `final` | Касса жмёт ✅/❌ на `[ДЕПОЗИТ]`; бот дописывает итог в эту карточку | правка `deposit.receipt` |
| `cancelled` | Бот дописывает «❌ Заявка #N отменена» в карточку или публикует это отдельным ответом | правка `deposit.request` / отдельное сообщение |

Методы различаются этапами `requisites`–`sent` и формой финала. Остальное общее.

### 3.1 Кнопки (видны в версиях сообщения до правки)

| Карточка | Кнопки | Что делают |
|---|---|---|
| Заявка (ТРЕУГОЛЬНИК, ПОЛИГОН) | `Выдать реквизит` · `🔄 Сменить платформу` | Выдача реквизита / перенос заявки в другую кассу |
| Заявка после «Сменить платформу» | список платформ по строке: `<Название> \| <min> - <max> \| <тип>` … и `◀️ Назад` | Выбор кассы-получателя |
| `[ДЕПОЗИТ]` | `🔒` / `❌ Отклонить` · `✅ Подтвердить` | Финал |

После финала или отмены бот снимает кнопки правкой.

### 3.2 Карточка `[ДЕПОЗИТ]`

- Отдельное сообщение бота (не правка заявки), всегда с вложением: PDF (`MessageMediaDocument`, `application/pdf`) или фото (`MessageMediaPhoto`). Имя файла — от банка игрока (`receipt_20.11.2026.pdf`, `ozonbank_document_….pdf`, `Документ-….pdf`, `Чек об операции, ….pdf`).
- Поля: `Deposit ID`, `Пользователь … ID`, `Тип пользователя`, `Успешных депозитов: <метка> N`, `Номер счёта`, `Сумма пополнения` (с пробелом тысяч), `Метод оплаты`.
- Итог дописывается правкой через пустую строку:
  - `✅ Успех: Операция прошла успешно` → `final/success`;
  - `✅ Подтверждено - зачислите в приложении` → `final/success` (Полигон);
  - `❌ Заявка #<Deposit ID> отменена` + строка инициатора → `final/rejected`.
- Карточка `[ДЕПОЗИТ]` может появиться у заявки, которую потом отклоняют («Отклонена кассиром»): чек пришёл, а денег нет.
- У Top Pay итог в карточку не дописывается, подтверждение идёт отдельным сообщением (см. §14).

### 3.3 Блок отправки реквизита (`deposit.sent`)

Бот публикует ответом на сообщение с реквизитом (у треугольника — на ответ кассира; `reply_to_top_id` = карточка заявки):

```
Реквизиты успешно отправлены пользователю ID <TGID>

Переведите точную сумму
36 000 рублей

Нажмите, чтобы скопировать!
💳 Реквизиты: 79XXXXXXXXX
🏦 Банк: ВТБ
📇 ФИО получателя: Не указан

🆘 Контакт поддержки: <контакт кассы>

Бонус: 0,77 руб
Итоговая сумма: 36 000,77 руб
```

- `Бонус` — копейки, которые бот добавляет к сумме, чтобы сумма платежа была уникальной. `Итоговая сумма` = сумма + бонус: её игрок и переводит, она же — `Сумма пополнения` в `[ДЕПОЗИТ]`. Десятичная запятая, пробел тысяч, хвост ` руб`. Бонус может быть и больше рубля (`Бонус: 7,66 руб`).
- `💳 Реквизиты`, `🏦 Банк`, `📇 ФИО получателя` бот берёт из реквизита кассы: строка 1 → реквизит, строка 2 → банк, строка 3 → ФИО (если нет — `Не указан`). Остальные строки ответа кассира идут в блок `📋 Инструкции:` (`• 470`). Названия банков бот иногда нормализует (`втб‼️` → `ВТБ`, `Тбанк‼️` → `Т-Банк`, `альфа‼️` → `Альфа Банк`), иногда оставляет как есть (`валбериз‼️`).
- `🆘 Контакт поддержки` — текст кассы: `@username` с подписью или список ссылок `t.me/…`.
- Реквизит — номер телефона (`79…`, `89…`, `+79…`) или номер карты (16 цифр, иногда группами по 4).

## 4. Отмены

Строка `❌ Заявка #<Deposit ID> отменена`, следующая строка — `Инициатор: <кто> · Причина: <текст>`.

Доставка отмены — одним из двух способов:
1. **Правка карточки** — блок дописан в конец заявки (или `[ДЕПОЗИТ]`) через пустую строку. Типично для Blade, Hermes, SprintPay, Top Pay.
2. **Отдельное сообщение** бота — ответ (`reply_to`) на карточку заявки, текст только из двух строк отмены. Типично для Полигона, Favorit; встречается и у других касс.

Причины за 14 дней по всем DOP-группам:

| Инициатор | Причина | Доля | Смысл |
|---|---|---|---|
| пользователь | `Отменена пользователем для создания новой заявки` | ≈ 62 % | Игрок пересоздал заявку (другая сумма/метод). Новая заявка — другой Deposit ID. |
| пользователь | `Отменена пользователем` | ≈ 14 % | Игрок отказался. |
| система | `Заявка отклонена системой` | ≈ 8 % | Платформа сняла заявку (в т. ч. при выключении метода без кассы для перенаправления). |
| система | `Время ожидания оплаты истекло (15 минут)` | ≈ 6 % | Таймаут оплаты; минуты в скобках. |
| пользователь | `Пользователь выбрал другого кассира` | ≈ 4 % | Игрок ушёл в другую кассу. |
| кассир | `Отклонена кассиром` | ≈ 2 % | Кассир нажал ❌ без текста. |
| кассир | свободный текст | ≈ 4 % | `пересоздайте на 3000`, `Создайте на 1000 или 2000`, `Создайте на … на кассу Камелот`, `Игрок заблокирован кассиром`, `Оплата не поступила в отведённое время`, `У вас уже есть незавершённая заявка`, `Депозит недоступен для этого аккаунта`, `arbitr`. |

После отмены статус фиксирован: дальнейшие правки не меняют исход (так работает `deposits`).

## 5. Суммы

| Где | Пример | Формат |
|---|---|---|
| Заявка, `Сумма пополнения` | `36000.00` | точка, без пробела тысяч; у Полигона бывает уже с копейками: `1000.13` |
| `deposit.sent`, `Переведите точную сумму` | `36 000 рублей` | пробел тысяч, без копеек |
| `deposit.sent`, `Бонус` / `Итоговая сумма` | `0,77 руб` / `36 000,77 руб` | запятая, пробел тысяч |
| `[ДЕПОЗИТ]`, `Сумма пополнения` | `36 000.77` | точка, пробел тысяч; обычно = итоговой сумме |
| Ссылки на заявку в служебных сообщениях | `Заявка #1 477 606` | Deposit ID с пробелами тысяч — убрать пробелы |

Сумма в `[ДЕПОЗИТ]` — сумма чека; она может отличаться от запрошенной (Hermes: метод `950 - 950`, чек `255.81`).

## 6. Перенаправление

- В исходной кассе в карточку дописывается: `🔄 Депозит перенаправлен на платформу <Название> | <min> - <max> | <тип>`. Для этой кассы заявка закрыта.
- В кассе-получателе публикуется новая карточка с той же `Deposit ID` и заголовком с ` 🔄 ПЕРЕНАПРАВЛЕН`; в ней часто есть `Накопленный бонус`. Дальше заявка идёт по методу кассы-получателя.
- В Autocash это одна заявка с историей касс (`deposits.kassas`).
- Массовое перенаправление при выключении метода: бот отвечает отчётом
  ```
  ✅ Метод оплаты <метод> успешно выключен.
  📊 Перенаправление депозитов:
  • Всего обработано: 3
  • Перенаправлено: 0
  • Не удалось: 3
  ⚠️ Для неперенаправленных депозитов нет подходящих активных платформ.
  ```

## 7. Связывание сообщений одной заявки

| Сообщение | Ключ связи |
|---|---|
| Карточка заявки | `Deposit ID` в тексте; msg_id карточки → `deposits.request_msg_id` |
| Ответ кассира с реквизитом | `reply_to` = msg_id карточки заявки (или сообщения «⚠️ Проблема с реквизитом!») |
| «Реквизиты успешно отправлены пользователю ID <TGID>» | `reply_to` = ответ кассира, `reply_to_top_id` = карточка заявки; TGID в тексте |
| `[ДЕПОЗИТ]` | `Deposit ID` в тексте |
| Отдельная отмена | `reply_to` = карточка; `#<Deposit ID>` в тексте |
| «📸 Скриншот ошибки реквизита» / «⚠️ Проблема с реквизитом!» | `Заявка #<Deposit ID>` в тексте (с пробелами тысяч в первом) |
| Top Pay «✅ Реквизиты выданы» / «✅ Депозит принят» | `reply_to` = карточка заявки; `TG: <TGID>` / `#<Deposit ID>` |

Порядок прихода не гарантирован: `[ДЕПОЗИТ]` по одной заявке может прийти раньше, чем отмена другой, а заявки разных игроков перемежаются. У одного игрока подряд бывает несколько заявок (пересоздания) — различать по Deposit ID.

**Правки.** Карточки заявки и `[ДЕПОЗИТ]` бот правит по мере смены этапа. Последняя версия текста — итоговое состояние; промежуточные версии (с кнопками, без итога) нужны, чтобы восстановить время этапов. Правка с `edit_hide=true` — служебная (например, подгрузка превью ссылки), смысл текста не меняет.

## 8. Проблема с реквизитом

Игрок сообщает, что реквизит не принимает перевод:

```
📸 Скриншот ошибки реквизита
Заявка #1 477 606
```
(сообщение бота с фото), затем:
```
⚠️ Проблема с реквизитом!

Заявка #1477606
📸 Пользователь приложил скриншот ошибки (см. сообщение выше)

Пожалуйста, отправьте новые реквизиты.
```

Кассир отвечает на «⚠️ Проблема с реквизитом!» новым реквизитом, бот публикует новое «Реквизиты успешно отправлены…». У заявки становится несколько выданных реквизитов. Правкой в «⚠️ Проблема…» может дописаться отмена заявки. Для автоматически выданных реквизитов бот добавляет ссылку на запись: `Реквизит #805, у него ещё 1 запись: /edit_req 805 или /del_req 805`.

## 9. Служебные сообщения о методах

Команды пишет кассир, отвечает бот кассовой платформы.

| Команда кассира | Ответ бота | Тип |
|---|---|---|
| `/turn_off <method_id>` | `✅ Метод оплаты <метод> успешно выключен.` (+ отчёт о перенаправлении, §6) | `method.off` |
| `/turn_on <method_id>` | `Метод оплаты <метод> успешно включен.` | `method.on` |
| `/change_dep_limits <method_id>` | Диалог: `Введите новый нижний лимит (min_value) или '-' для пропуска:` → число → `Введите новый верхний лимит (max_value) или '-' для пропуска:` → число → `Лимиты для метода <метод> обновлены: min=1 003, max=1 003` | `method.limits` |

`<метод>` в ответах — полное название с текущими лимитами. Связь `method_id` ↔ название — по паре «команда → ответ бота».

Автоотключение платформой:
```
⚠️ Автоматическое отключение платформы

Ваша платформа Hermes Cash | 490 - 490 | CБП/Карты [PDF] была отключена,
т.к. вы долго не выдавали реквизиты.

Вы можете продолжить работу включив платежные методы /turn_on id

📊 Обработка депозитов:
• Всего: 1
• Перенаправлено: 0
• Не удалось перенаправить: 1
```

Команды метода «Предустановленная сумма» (`/set_sum`, `/del_req`, `/edit_req`, `/sum`) — в §13.

## 10. Прочие сообщения в DOP-группах

- Сообщения админов платформы и менеджеров касс (трафик, просьбы включить метод, теги поддержки) — свободный текст; часть — от анонимного администратора (`sender_id` пуст).
- Кассиры отвечают скриншотами без текста (подтверждения, споры).
- В DOP-группах изредка встречается `[ВЫВОД]` — заявка на вывод, обрабатывается вне модуля депозитов.

|---|---|
| `Пользователь:` | Имя с пробелами (`Андрей Долгов ID: …`), из точек/символов (`…`, `......`), кириллица, `@username`. TGID — последнее `ID: \d+` в строке. |

# Часть II. Методы

## 12. «Треугольник»

Основной метод: игрок → платформа → касса → игрок. Платформа создаёт заявку, кассир вручную выдаёт реквизит, бот пересылает его игроку, игрок платит и присылает чек, кассир подтверждает. Так работает большинство касс (Blade, Hermes, Monetra, MONGI, Paytronix, RedWine, Fast Cash, Misuta, Kamelot, Pulpy, Premier и др.).

### Признаки

- Заголовок `[ДЕПОЗИТ ТРЕУГОЛЬНИК]` (или с ` 🔄 ПЕРЕНАПРАВЛЕН`).
- Строка `Оператор, выдайте реквизиты!`.
- Сразу после публикации (правкой, вместе с превью ссылки) дописывается подсказка формата:
  ```
  Пожалуйста, введите реквизиты для оплаты в формате:

  4111 1111 1111 1111
  Мбанк
  Иванов Иван Иванович
  t.me/mbkasssa_support
  ```
  Это шаблон, а не реквизит: номер `4111 1111 1111 1111` и `Иванов Иван Иванович` не извлекать.

### Этапы

| # | Кто | Сообщение | Этап |
|---|---|---|---|
| 1 | бот | Карточка `[ДЕПОЗИТ ТРЕУГОЛЬНИК]`, кнопки `Выдать реквизит` · `🔄 Сменить платформу` | `created` |
| 2 | кассир | **Ответ (reply) на карточку** с реквизитом, 2–4 строки | `requisites` |
| 3 | бот | Ответ на сообщение кассира: «Реквизиты успешно отправлены пользователю ID <TGID>…» | `sent` |
| 4 | бот | Новая карточка `[ДЕПОЗИТ]` с PDF/фото чека, кнопки `🔒` / `❌ Отклонить` · `✅ Подтвердить` | `receipt` |
| 5 | бот | Правка `[ДЕПОЗИТ]`: `✅ Успех: Операция прошла успешно` или `❌ Заявка #N отменена` | `final` |

Отмена возможна на любом этапе до 5. Типичное время: реквизит — до минуты, чек — 1–15 минут после реквизита.

### Ответ кассира (этап 2)

Свободный текст, порядок строк фиксирован ботом: реквизит → банк → ФИО → прочее.

| Касса | Пример ответа | Особенность |
|---|---|---|
| Blade | `"79XXXXXXXXX`<br>`втб‼️`<br><br>`@sup_BLADE - Ваш личный менеджер 😘"` | Обёрнут в кавычки, банк с `‼️`, строка контакта. ФИО нет → `Не указан`; контакт уходит в `🆘 Контакт поддержки`. |
| Hermes | `+79XXXXXXXXX`<br>`сбер`<br>`470` | Третья строка — сумма; бот кладёт её в `📋 Инструкции: • 470`, ФИО `Не указан`. |
| Полигон | `+79XXXXXXXXX`<br>`Ozone банк`<br>`Третьяков Д А` | Третья строка — ФИО получателя (см. §15). |

Ответ кассира может прийти не reply, а отдельным сообщением; тогда связь с заявкой — только через последующее «Реквизиты успешно отправлены пользователю ID <TGID>» (TGID + `reply_to_top_id`).

### Особенности касс

#### Blade
- Метод: `[СБП] [Карты] BLADE [PDF] <min> - 500 000`, нижний лимит меняется в течение дня (1 000…10 000).
- Часть заявок уходит на другие платформы: `🔄 Депозит перенаправлен на платформу Pay T 🟠 | 1 500 - 50 000 | СБП`.
- Список платформ при «Сменить платформу» (пример): `⚡️Pulpy [VIP]⚡️ | 3 000 - 500 000 | СБП Быстрый`, `🔥 Premier =VIP= 🔥 | …`, `Sportlive 💎 | …`, `Pay T 🟠 | …`, `Trust Cash ⛄️ | …`, `Falcone Cash 🦅 | …`, `Sportlive Reserv💎 | …`, `👸QUEENCASH👸 | …`, `Monetra❤️ | …`, `Misuta 👑 | …`, `FAST CASH  💰 | …`, `FAVORIT ♦️ | …`, `🦢 Amun Cash 🦢 | …`, `Kamelot 💫 | …`, `REIGNCASH | …`.

#### Hermes Cash
- Методы с фиксированной суммой: `Hermes Cash СБП/Карты 470 - 470`, `Hermes Cash 2 СБП/Карты 950 - 950`. Кассир держит включённой одну-две суммы и постоянно их меняет циклом `/turn_off` → `/change_dep_limits` → `/turn_on` (десятки раз в час). Сумма метода = сумма заявки.
- В одну минуту приходит пачка заявок на одну сумму; лишние отменяются игроками или системой.
- Сумма в `[ДЕПОЗИТ]` может отличаться от суммы метода (чек на `255.81` по методу `950 - 950`).

#### SprintPay (треугольник)
- В SprintPay DOP основной метод — «Предустановленная сумма» (§13); треугольник бывает по методу `СБП |  | SprintPay 1 000 - 5 000`.

## 13. «Предустановленная сумма»

Касса заранее загружает пары «сумма + реквизит». Игрок выбирает одну из доступных сумм, бот выдаёт привязанный к ней реквизит сразу в карточке заявки — без участия кассира. Кассир участвует только в пополнении сумм и в финале. Наблюдается у SprintPay (`Конкретная сумма SprintPay 500 - 100 000`) и Queen Cash (`QueenCash СБП PRESET | …`).

### Признаки

- Заголовок `[ДЕПОЗИТ ПРЕДУСТАНОВЛЕННАЯ СУММА]`.
- В карточке блок `🤖 Реквизит #<req_id> выдан автоматически:`.
- Строки `Оператор, выдайте реквизиты!` нет.

### Карточка заявки

```
[ДЕПОЗИТ ПРЕДУСТАНОВЛЕННАЯ СУММА]
Deposit ID: <Deposit ID>
Пользователь: <имя> ID: <TGID>
Тип пользователя: USER
Успешных депозитов: 🟢 0 (всего: 104)
Номер счёта: <MelID>
Сумма пополнения: 2000.00
Метод оплаты: Конкретная сумма SprintPay 500 - 100 000
🤖 Реквизит #799 выдан автоматически:
💳 Реквизиты: 2204 XXXX XXXX XXXX
🏦 Банк: Озон Банк

📝 Чек присылайте в PDF
🆘 Контакт поддержки: @SprintPay_melbet
```

- `Реквизит #<req_id>` — id записи реквизита в платформе (используется в `/del_req`, `/edit_req`).
- Строки после `🏦 Банк` — инструкция кассы, заданная при загрузке суммы.
- `Сумма пополнения` — ровно загруженная сумма.

### Этапы

| # | Сообщение | Этап |
|---|---|---|
| 1 | Карточка с авто-выданным реквизитом. Создание и выдача реквизита — одно сообщение. | `created` + `requisites` + `sent` |
| 2 | `[ДЕПОЗИТ]` с чеком; `Сумма пополнения` = загруженная сумма без копеечного бонуса (`2 000.00`) | `receipt` |
| 3 | Правка `[ДЕПОЗИТ]`: `✅ Успех: Операция прошла успешно` или `❌ … Инициатор: кассир · Причина: Отклонена кассиром` | `final` |

Сообщения «Реквизиты успешно отправлены…» у этого метода нет.

### Пул сумм

Каждая загруженная сумма выдаётся одной заявке и уходит из пула. **[трактовка]** Если заявку отклонили, сумма возвращается в пул — так следует из ответа `/del_req` «сумма после отклонения не вернётся» для удалённых записей. Лимит — 50 сумм на метод.

Сообщения бота о пуле (без reply):
- `⚠️ Конкретная сумма SprintPay 500 - 100 000 (ID 364): осталась 1 предустановленная сумма, добавьте новые` (также `осталось 2 предустановленные суммы`);
- `⛔ Конкретная сумма SprintPay 500 - 100 000 (ID 364): предустановленные суммы закончились, метод скрыт у пользователей. Добавьте новые: /set_sum 364 …`.

`(ID 364)` — `method_id`.

### Команды кассира

#### `/set_sum <method_id> <сумма>` — загрузить сумму

Команда, следующие строки — реквизит, банк, затем текст инструкции:
```
/set_sum 364 1000
2200XXXXXXXXXXXX
Т-Банк

@SprintPay_melbet
Чек присылайте в PDF
```
Ответ:
```
💰 Конкретная сумма SprintPay 500 - 100 000 (ID 364)
💳 Реквизит #807 (новый). Пользователь увидит:
💳 Реквизиты: 2200 XXXX XXXX XXXX
🏦 Банк: Т-Банк

📝 Чек присылайте в PDF
🆘 Контакт поддержки: @SprintPay_melbet
Добавлено: 1 000
Обновлено: —
Дубли: —
Не добавлено (лимит 50 сумм): —
Сумм у метода: 1 из 50
```
Бот форматирует номер карты группами по 4, распознаёт `@контакт` и `Чек присылайте в PDF` и раскладывает по строкам `🆘`/`📝`.

#### `/sum <method_id>` — список загруженного
```
💰 Конкретная сумма SprintPay 500 - 100 000 (ID 364) · сумм 1 из 50
💳 #811 · ВТБ · 79XXXXXXXXX
   2 000
💳 #817 · ВТБ · 79XXXXXXXXX
   2 000
```

#### `/del_req <req_id>` — удалить реквизит со всеми суммами
```
🗑 Реквизит #805 · Конкретная сумма SprintPay 500 - 100 000 (ID 364)
Удалено: 1 045 ×0
Заявки в работе по удалённым записям (сумма после отклонения не вернётся): 1 045 (заявка #1474836)
Нет в списке: —
Реквизит удалён
Доступно сумм: 0
```
`×0` — у суммы не осталось свободных записей (все в работе). Заявка в работе по удалённому реквизиту продолжается.

#### `/edit_req <req_id>`
Упоминается ботом в «⚠️ Проблема с реквизитом!» как способ заменить реквизит.

`/turn_on`, `/turn_off` — как у всех методов (§9). Кассир выключает метод, когда нет загруженных сумм или клиентов.

### Особенности

- Одна сумма — один реквизит; у разных сумм могут быть разные реквизиты и банки.
- Жалоба «📸 Скриншот ошибки реквизита» → «⚠️ Проблема с реквизитом!» с подсказкой `Реквизит #805, у него ещё 1 запись: /edit_req 805 или /del_req 805`.
- Игроки часто создают заявку на одну и ту же сумму повторно (одна и та же сумма и реквизит в нескольких заявках подряд, большинство отменены).

## 14. Top Pay

Касса Top Pay подключена к платформе интеграцией: реквизит выдаёт и оплату подтверждает автоматика кассы, кассиры в группе не пишут. Группа: `Top pay #1 DOP`. Все сообщения — от бота кассовой платформы.

### Признаки

- Заголовок `[ДЕПОЗИТ ТРЕУГОЛЬНИК]`, метод `Top Pay <сумма>`: `Top Pay 500`, `Top Pay 1 000` — фиксированная сумма, без диапазона.
- После `Оператор, выдайте реквизиты!` строка `🏦 Банк: <банк игрока>` — банк, который игрок выбрал при создании заявки: `Сбер`, `Т-Банк`, `Озон Банк`, `Альфа`, `ЮMoney`, `Другой банк`.
- Ответы бота `✅ Реквизиты выданы` и `✅ Депозит принят #…`.

### Этапы

| # | Сообщение | Этап |
|---|---|---|
| 1 | Карточка `[ДЕПОЗИТ ТРЕУГОЛЬНИК]` с `🏦 Банк:` | `created` |
| 2 | Ответ бота на карточку (обычно < 1 мин): реквизит выдан | `requisites` + `sent` |
| 3 | `[ДЕПОЗИТ]` с PDF; `Сумма пополнения` с копейками (`500.35`) | `receipt` |
| 4 | Ответ бота на карточку заявки: депозит принят | `final/success` |

#### Этап 2 — «Реквизиты выданы»
```
✅ Реквизиты выданы
💳 Sberbank •••• 6434 / —
TG: <TGID>
```
- `💳 <банк> •••• <последние 4 цифры> / <…>` — банк кассы латиницей (`Sberbank`, `T-Bank`, `OzonBank`, `AlfaBank`, `VTB`, `OTPBank`, `MTSBANK`) и маска реквизита. После `/` в наблюдениях всегда `—`.
- Банк выдачи может отличаться от выбранного игроком (`ЮMoney` → `MTSBANK`/`T-Bank`, `Другой банк` → `Sberbank`).
- `TG:` — TGID игрока; вместе с `reply_to` связывает сообщение с заявкой.
- Это сообщение заменяет и ответ кассира, и «Реквизиты успешно отправлены…» треугольника.

#### Этап 3 — `[ДЕПОЗИТ]`
- Формат общий. `Сумма пополнения` = сумма метода + копеечный бонус (`1 000.52`).
- Имя файла чека иногда содержит последние цифры карты (`На_карту_6434_20.11.26.pdf`) — совпадают с маской из этапа 2.
- Карточка остаётся без строки итога: финал приходит отдельным сообщением (этап 4).

#### Этап 4 — «Депозит принят»
```
✅ Депозит принят #<Deposit ID> | @username
💰 1000.52₽ | txn: 8257909345
```
- Reply на карточку заявки (не на `[ДЕПОЗИТ]`).
- ` | @username` есть, если у игрока есть username.
- `💰` — зачисленная сумма (точка, без пробела тысяч, `₽`), равна `Сумма пополнения` в `[ДЕПОЗИТ]`.
- `txn` — id транзакции во внешней системе Top Pay.
- Приходит через 0–8 минут после `[ДЕПОЗИТ]`. Это единственный сигнал успешного финала: для Autocash `deposit.receipt` здесь не завершает заявку, финал — по этому сообщению.

### Отмены

Дописываются правкой в карточку заявки (§4). Наблюдаемые причины: `Отменена пользователем`, `Отменена пользователем для создания новой заявки`, `Время ожидания оплаты истекло (15 минут)`. Отмена может прийти после «✅ Реквизиты выданы» (игрок получил реквизит и не оплатил).

### Объёмы (200 сообщений, ≈ 1 час)

≈ 56 выдач реквизита, ≈ 41 чек, ≈ 44 «Депозит принят», ≈ 13 отмен. Суммы — 500 и 1 000.

## 15. «Полигон»

Полигон — площадка, где заявки обрабатывают подключаемые на смену кассы-«магазины» (`MOTOR STORE`, `Sky Pay`, `FIFAPAY Shop`, `Turbo Money Shop` …). Кассир магазина приходит в группу на смену, выдаёт реквизиты (с ФИО получателя), а после оплаты зачисляет депозит в приложении **Тимкеш** и подтверждает это скриншотом. Смену и проверки ведёт бот-координатор.

Группы: `Полигон DOP`, `Полигон Start/Blue/Green/Red/Yellow/newbie/main DOP`, `Polygon Supervisor/Superviser KG/Reserv/TEST/Auto Newbie/KG Glusha Cash/Polkovnik Shop DOP`, частично `BunnyPay DOP`.

### Участники

| Кто | Как узнать | Что пишет |
|---|---|---|
| Бот кассовой платформы | TGID `7185799444` | Карточки `[ДЕПОЗИТ ПОЛИГОН]`, «Реквизиты успешно отправлены…», отмены |
| Бот-координатор Полигона | TGID `7973286850` | Начало/конец смены, проверка баланса и зачислений, «Взяли заявок…» |
| Кассир магазина | пользователь, меняется от смены к смене | Реквизиты, скриншоты Тимкеша, реплики |
| Менеджер / админ | пользователь или анонимный админ (`sender_id` пуст) | Запуск и завершение смены: «готовы?», «работаем», «Закончим на сегодня?», «Свободен!» |

### Признаки

- Заголовок `[ДЕПОЗИТ ПОЛИГОН]` (в заявке часто с ` 🔄 ПЕРЕНАПРАВЛЕН`).
- Метод с символом `⬡`: `Полигон Моментальный ⬡  1 000 - 3 000`, `Полигон Быстрый ⬡ …`, `Полигон RED ⬡ | …`, `Полигон Новый ⬡ …`, `Полигон Обучение ⬡ …`, `Полигон Blue/Yellow/Green/Reserv ⬡ …`, `Polygon  ⬡ …`. Лимиты небольшие (1 000–3 000).
- Игрок указан строкой `ID: <TGID>` вместо `Пользователь: … ID: …`.

### Смена кассы

Сообщения бота-координатора, по порядку:

1. Начало:
   ```
   Касса MOTOR STORE
   Начала работу: 16:45
   Общая сумма: 8100.00 ₽
   ```
   `Общая сумма` — объём заявок, который магазин готов принять за смену.
2. Проверка баланса:
   ```
   Пришлите скриншот ГЛАВНОГО экрана кассы из Тимкеша — целиком, вместе с номером кассы в шапке и строкой «Лимит кассы».
   Пока баланс не подтверждён, заявки на кассу не идут.
   ```
   Кассир присылает фото. При неудаче: `Не удалось разобрать скриншот (попытка 1 из 3).` + требования к снимку.
3. Допуск:
   ```
   Касса MOTOR STORE подтверждена.
   Лимит кассы (деньги): 8147.37 ₽
   Баланс (оборот, не деньги): 7726.00 ₽
   Начинаем набор.
   ```
4. В ходе смены: `Взяли заявок на сумму 4300.00 ₽, ждём оплату 15 минут`, `Продолжаем брать заявки ещё на 10000.00 ₽`.
5. Конец:
   ```
   Касса MOTOR STORE
   Закончила работу: 17:26
   Обработанная сумма: 7300.00 ₽
   ```

### Этапы заявки

| # | Кто | Сообщение | Этап |
|---|---|---|---|
| 1 | бот | `[ДЕПОЗИТ ПОЛИГОН]` + `Оператор, выдайте реквизиты!` + подсказка формата; кнопки `Выдать реквизит` · `🔄 Сменить платформу` | `created` |
| 2 | кассир | Реквизит тремя строками: номер, банк, ФИО — reply на карточку или отдельным сообщением | `requisites` |
| 3 | бот | «Реквизиты успешно отправлены пользователю ID <TGID>…» с ФИО получателя, reply на сообщение кассира | `sent` |
| 4 | бот | **Новая** карточка `[ДЕПОЗИТ ПОЛИГОН]` с `Deposit ID`, вложением чека (PDF/фото); кнопки `🔒` / `❌ Отклонить` · `✅ Подтвердить` | `receipt` |
| 5 | бот | Правка карточки этапа 4: `✅ Подтверждено - зачислите в приложении` | `final/success` |
| 6 | координатор → кассир → координатор | Проверка зачисления в Тимкеше (ниже) | после `final` |

#### Этап 2 — реквизит
```
+79XXXXXXXXX
Ozone банк
Третьяков Д А
```
ФИО — реальное имя получателя (часто сокращённое: `Юлия Михайловна Н`). Кассир смены обычно выдаёт один и тот же номер на все заявки, меняя банк.

#### Этап 3 — отправка
Как в §3.3, с заполненным `📇 ФИО получателя` и контактами поддержки списком:
```
🆘 Контакт поддержки: 
t.me/mbkasssa_support
t.me/mbkassa_opslead
t.me/important_issues_rucash - для связи по спорным вопросам
```

#### Этап 6 — проверка зачисления
Координатор отвечает на карточку чека:
```
Проверка зачисления по этой заявке.
Пришлите скриншот из Тимкеша: карточку «Детали транзакции» по этой операции либо экран «Последние транзакции», где она видна.
Пока зачисление не подтверждено, новые заявки на кассу не идут.
```
Кассир присылает фото, координатор отвечает на ту же карточку: `Зачисление по этой заявке подтверждено. Продолжаем набор.` Обычно 1–3 минуты. Пока проверка не закрыта, касса не получает новых заявок.

«Зачислите в приложении» означает: кассир магазина зачисляет депозит игроку в Тимкеше. Админы могут разрешить отложить зачисление: «Выдача реквизитов в приоритете, зачислить можно позже».

### Особенности

- Отмены приходят отдельными сообщениями бота — reply на карточку заявки (§4, способ 2).
- `Тип пользователя` в заявке бывает `TRUSTED` или `NEW`; в карточке чека того же игрока — `USER`.
- `Сумма пополнения` в заявке: в ранних карточках — уже с копейками (`1000.13`), позже — круглая с отдельной строкой `Накопленный бонус: 0.27`.
- В ранних карточках заявки (до 2026-11-12) строки `Deposit ID` нет; она появляется в карточке чека. Связь такой заявки — через reply-цепочку и TGID.
- Доля карточек ` 🔄 ПЕРЕНАПРАВЛЕН` среди всех карточек `[ДЕПОЗИТ ПОЛИГОН]` сильно зависит от группы: `Полигон DOP` ≈ 9 %, `Полигон Red DOP` ≈ 49 % (14 дней).
- Кассир отвечает скриншотами на карточки чеков и вне проверки координатора — это подтверждения зачисления.

## 16. NSPK (СБП QR-линк)

Касса выдаёт игроку не номер карты или телефона, а ссылку на оплату через QR-код СБП (НСПК). Наблюдается в `Favorit Cash DOP`, метод `[PDF] QR-КОД 📱 | 10 000 - 100 000`. Редкий: ≈ 50 карточек за 14 дней.

### Признаки

- Заголовок `[ДЕПОЗИТ NSPK (СБП QR-ЛИНК)]`.
- Призыв `Оператор, выдайте QR-ссылку СБП!`.
- Пустая строка между `Номер счёта` и `Сумма пополнения`.

```
[ДЕПОЗИТ NSPK (СБП QR-ЛИНК)]
Deposit ID: <Deposit ID>
Пользователь: <имя> ID: <TGID>
Тип пользователя: USER
Успешных депозитов: 🟢 2
Номер счёта: <MelID>

Сумма пополнения: 13000.00
Метод оплаты: [PDF] QR-КОД 📱 | 10 000 - 100 000
Оператор, выдайте QR-ссылку СБП!
```

### Этапы

`created` → выдача QR-ссылки кассой → **[трактовка]** `[ДЕПОЗИТ]` с PDF и финал по общей схеме §3. Отмены — отдельным сообщением бота, reply на карточку.

Метод QR-КОД может получать и обычные заявки `[ДЕПОЗИТ ТРЕУГОЛЬНИК] 🔄 ПЕРЕНАПРАВЛЕН` с `Оператор, выдайте реквизиты!` — тогда это поток треугольника (§12).

### Открыто

Формат сообщения кассира с QR-ссылкой и ответа бота на него в выборке не попался (все наблюдаемые NSPK-заявки отменены до выдачи). Дополнить по первому реальному образцу.

#### Запросы

Последние 200 сообщений группы:
```sql
SELECT r.telegram_message_id, r.sender_id, r.reply_to_message_id, r.message_date, r.edit_date, r.text
FROM raw_messages r
JOIN chat_registry c ON c.chat_id = r.chat_id AND c.telegram_account_id = r.telegram_account_id
WHERE c.title = 'Blade Dop'
ORDER BY r.telegram_message_id DESC
LIMIT 200;
```

Все сообщения одной заявки в группе:
```sql
SELECT telegram_message_id, reply_to_message_id, sender_id, message_date, text
FROM raw_messages
WHERE chat_id = $1
  AND (text LIKE '%Deposit ID: ' || $2 || '%' OR text LIKE '%#' || $2 || '%')
ORDER BY telegram_message_id;
```
Дополнить ответами на найденные карточки (`reply_to_message_id IN (…)`) — так находятся ответ кассира и «Реквизиты успешно отправлены…».

История правок карточки (кнопки, промежуточный текст):
```sql
SELECT v.snapshot_json
FROM seeker_source_versions v
JOIN raw_messages r ON r.id = v.raw_message_id
WHERE r.chat_id = $1 AND r.telegram_message_id = $2;
```

Запросы по `text LIKE` по всем DOP-группам за недели идут минуты — ограничивать `chat_id` и `message_date`.
