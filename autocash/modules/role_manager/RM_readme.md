# RM — Role Manager

Первый модуль Autocash. Выдаёт роли группам. По роли ядро решает, читать группу или нет.
Решения: `docs/decisions.md`, D-RM-1…D-RM-6.

## Команды

| Команда | Где | Что делает |
|---|---|---|
| `/grole <ID> <роль>` | любой чат | установить роль группе |
| `/grole <ID>` | любой чат | показать роль группы |
| `/grole <ID> -<роль>` | любой чат | снять роль: группа получает роль по умолчанию |
| `/rm ?` | в группе | показать роль этой группы |

Права — матрица `permissions` (команды `grole`, `rm`); по умолчанию у ролей admin и dev есть все команды.
Обе команды принимаются и в группах, которые не читаются (роль `other`): сохраняется только сообщение с командой (D-RM-4).

### ID группы

Принимаются все четыре формы: `3845234572634`, `1003845234572634`, `-3845234572634`, `-1003845234572634`.
Записывается без минуса и без «100» супергрупп: `3845234572634` (D-RM-3).
Группа ищется среди групп, где состоят аккаунты пула, и среди групп с ролью. Если группа не найдена, команда отказывает: роль не выдаётся «вслепую».

## Роли

| Роль | Политика | Значит |
|---|---|---|
| `other` | `presence` | группа известна, сообщения не читаются, реакций нет. Роль по умолчанию для любой группы |

Роли переделываются с нуля, пока есть только `other`. Новая роль добавляется в конфиг:
1. `group_roles` — в список ролей;
2. `defaults.policy_by_role` — её политика: `full` (читать и обрабатывать), `meta`, `presence`, `ignore`. Без записи — `full`.

## Конфигурация

`config/groups.yaml`:

```yaml
group_roles: [other]
groups:
  3845234572634: other     # ID группы без минуса -> роль
```

- Модуль включается в `modules: {role_manager: {}}`.
- Роль по умолчанию — `defaults.group_role: other`.
- `/grole` переписывает файл тем же редактором, что и веб-админка: проверка, версия, журнал `config_changes` (автор, diff), применение без рестарта. Комментарии внутри переписанного файла теряются, поэтому `groups.yaml` — отдельный файл, который ведёт машина.
- Правка руками тоже работает: после неё `/reload`.

## Обратная связь

| Кому | Что |
|---|---|
| автору команды, в чат команды | всегда: результат или причина отказа |
| группе `logs` | каждое изменение роли: группа, было → стало, автор, версия конфигурации |
| группе, чья роль изменилась | **ничего** |

Если команда дана в самой группе, ответ на команду приходит туда же: это ответ автору, а не уведомление группе.
Чтобы участники группы не видели ответ, давайте `/grole` из лички с аккаунтом пула или из служебной группы.

## Что модуль пишет и куда

- Файл конфигурации `groups.yaml` (раздел `groups`).
- `config_changes` — через редактор конфигурации.
- Своих таблиц нет.

## Зависимости от ядра (явные)

- `autocash/core/config/schema.py` — поля `group_roles`, `groups`, `defaults.group_role`.
- `autocash/core/config/loader.py` — `bare_group_id`, `Runtime.group_role`, `Runtime.source`: роль из `groups` важнее ролей из `sources`.
- `autocash/core/gateway/gateway.py` — приём команд из групп, которые не читаются (`commands_any_chat`).
- `autocash/modules/api.py` — `Services.edit_config`, `Module.commands_any_chat`.
- `autocash/web/editor.py` — правка конфигурации (общая с веб-админкой).
