# QK2 — QuickCast2

Оператор набирает в поле ввода личного диалога аккаунта пула `ТРИГГЕР\` и **не отправляет**. QuickCast2 отправляет шаблон, и поле ввода очищается: триггер никуда не уходит, удалять нечего.
Решения: `docs/decisions.md`, D-QK2-1…D-QK2-4. Шаблоны — общий каталог QuickKast (`autocash/modules/quickkast`, `QK_readme.md`).

## Как это работает (D-QK2-1, D-QK2-2)

1. Клиент оператора сохраняет черновик в облако Telegram. Telegram сообщает об этом всем сессиям аккаунта (`UpdateDraftMessage`), в том числе Autocash.
2. Адаптер превращает его в событие `draft`. Gateway отдаёт его только хукам черновиков, черновик не хранится.
3. `draft()` решает по памяти: личный диалог (не «Избранное»), черновик оканчивается на `\`, остаток — триггер активного профиля.
4. Экспресс-полоса Outbox (`OBX_express`) отправляет шаблон сразу, с флагом `clear_draft`: Telegram сам очищает черновик. Очереди, шага антифлуда и темпа нет; приоритет 0, обычные задачи аккаунта идут после.
5. Времена — в `qk2_events`.

**Задержка зависит от клиента.** Черновик уходит в облако не на каждую букву, а после паузы в наборе (или при выходе из чата). `qk2_events` и `/qk2 stats` считают от прихода черновика в Autocash до ответа Telegram; паузу клиента они не видят.

## В диалоге

| Оператор набирает (не отправляя) | Что происходит |
|---|---|
| `ТРИГГЕР\` | случайный вариант шаблона |
| `ТРИГГЕР-N\` | вариант N |
| `ТРИГГЕР-list\` | все варианты одним сообщением |
| `ТРИГГЕР-N\`, где вариантов меньше N | «Для триггера … доступно только … вариант(а).» |

- Триггер — весь черновик без `\` в конце, с учётом регистра; пробелы по краям не важны.
- Если черновик — ответ на сообщение, шаблон уходит ответом на него же.
- Выключить в диалоге — `x` / `х` QuickKast (отправленным сообщением); это общий переключатель. `x\` и `v\` не поддерживаются (D-QK2-3).
- Не срабатывает: группы, «Избранное», черновик без `\`, неизвестный триггер, черновик с медиа.
- Отправленное сообщение `зд\` — не черновик, QK2 его не видит.

**Неудача.** Аккаунт на паузе (FloodWait) или ошибка Telegram — шаблон не отправляется, черновик остаётся в поле ввода, повтора нет. Запись в журнал монитора и в `logs` (не чаще раза в 10 минут, со счётчиком): `QK2: черновик «…» в диалоге … (аккаунт …) не отработал: <код>`.

**Повторы (D-QK2-4).** Клиент может сохранить один черновик несколько раз: пока шаблон диалога в пути (до 10 с), новые черновики диалога пропускаются; тот же черновик (текст + дата) срабатывает один раз.

## Команды

Только в группе с ролью tech, права — Admin и Dev. Без прав — в чате ничего, отказ в `logs`.

| Команда | Что делает |
|---|---|
| `/qk2` | справка |
| `/qk2 on` / `/qk2 off` | включить / выключить QuickCast2 (запись в `logs`) |
| `/qk2 stats` | за сутки: p50/p90/max от прихода черновика до ответа Telegram |

Шаблоны и профили — командами `/qk` (общие).

## Обратная связь (AGENTS.md, правило 9)

В диалог QK2 пишет только шаблон (или список вариантов / «доступно только N»), и только в ответ на черновик оператора с `\`.

## Конфигурация (`modules.quickcast2.config`)

| Ключ | По умолчанию | Что |
|---|---|---|
| `ttl_s` | 30 | срок задачи: не отправлено за это время — не отправляется |

Модуль требует `quickkast` в `modules` (его таблицы и каталог).

## Таблицы (`QK2_migrations/001_qk2.sql`)

- `qk2_settings` — включён ли QuickCast2;
- `qk2_events` — каждое срабатывание: `entered` (черновик), `draft_date`, `received_at` (черновик пришёл в Gateway), `matched_at`, `stored_at` (задача в PG), `sent_at` (ответ Telegram), задача Outbox, `status` (done / refused / failed), `reason`.

## Зависимости (явные)

- **Ядро:** событие `draft` (`telethon_client.draft_event`), `Gateway.draft_hooks`, `Module.draft_path` / `Module.draft`, `Services.express` → `OBX_express` с `clear_draft`.
- **QuickKast:** каталог `QK_catalog.shared`, таблицы `qk_*`.
- **Role Manager:** права `/qk2`, роль группы tech.
