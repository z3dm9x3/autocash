# TS — тикеты D-Ticket и WW-Ticket: проект следующих шагов

Статус: **проект, не согласован** (каждый шаг — после обсуждения, AGENTS.md правило 1). Реализовано: тикеты и C-ticket — `TS_readme.md`, D-TS-1…3; там правила уточнены (без «завис», «сутки», «зачисление», «реквизиты»; оба вида в одном сообщении — Q; Q в D/WW не переводится; тикеты не закрываются). Ниже — исходный анализ и наброски сбора ID, чека и кода. Источник — RAW личные сообщения Cash Monitor Dev (PG 5433, `raw_messages`, `chat_id > 0`),
15.08–19.11.2026: 32 590 сообщений, 1 817 диалогов игроков (без ботов и пользователей с ролями ADMIN/CASHER),
**3 136 обращений** (обращение — сообщение игрока после ≥ 6 ч тишины в диалоге).

## 1. Что показали данные

### Как обращаются

| Первые 60 с обращения (до ответа оператора) | доля |
|---|---|
| Проблема с депозитом: явные слова, PDF, пересланная заявка бота | 28 % |
| Проблема с выводом: слово «вывод/снял/выплата», код вывода, пересланная заявка | 16 % |
| «Деньги не пришли» — без указания, депозит это или вывод | 9 % |
| Только приветствие («Здравствуйте», «Привет», стикер) | 15 % |
| Невнятное («Так как быть?», «Чего ждём?», не по-русски) | 16 % |
| Напоминание по старому вопросу («актуально?», «ну что там», «?») | 5 % |
| Только ID / только картинка | 5,5 % |
| «Как сделать» (как вывести, есть ли реквизиты, какой город кассы) | 2,5 % |

60 с хватает: при 0 с невнятных 17,9 %, при 60 с — 16,5 %, при 120–300 с почти не меняется.

|---|---|---|---|---|---|

- Каждое 7-е обращение — повтор в течение 3 дней (D 99, W 63): нужен открытый тикет, а не новый.
- У 75 из 1 142 игроков в истории больше одного ID (несколько аккаунтов).

### Шаблоны операторов (как сейчас просят данные)

- 833 раза: «🟠 При обращении по депозиту укажите ваш ID и пришлите чек в формате PDF 📄 / 🟢 При обращении по выводу пришлите ID и код вывода 🔑».
- 83 раза: «Расскажите, пожалуйста, по какому вопросу обращаетесь?».
- 51 + 22 раза: «код заявки… из 4 символов», «пришлите код заявки на вывод».
- 42 раза: «Введен некорректный код, код из SMS не подходит. Используйте 4-символьный код вывода…» — игроки путают
  код вывода с SMS-кодом (4–7 цифр).

### Код вывода

4 символа `[A-Za-z0-9]`, регистр важен, обычно смесь: `tfVQ`, `5AKW`, `Upf6`, `M9mp`, `yzdm`, `2d6N`.
Где встречается: отдельным сообщением; рядом с ID (`1 758 918 313 / rywT`); после «код»; в пересланном сообщении бота
«Вывод с аккаунта 113 465 895 tfVQ». Ложные 4-символьные слова: `EPOS`, `Cash`, `RAMZ`, `USER`, `1WIN`, `Ozon`,
`Test`, `call`, азербайджанские/узбекские слова (`saat`, `geri`, `kimi`…).

## 2. Модель классификации

Обращение описывается тремя независимыми осями. Классификатор — правила со весами (П-2: словари и веса в YAML),
без ML: данных мало, правила проверяемы и объяснимы.

1. **Тема:** `D` (депозит) · `W` (вывод) · `?` (деньги, но неясно что) · нет.
2. **Намерение:** `PROBLEM` (не пришло / статус / проверьте) · `HOWTO` (как сделать) · `FOLLOWUP` (напоминание) ·
   `GREETING` · `UNCLEAR` · `OTHER` (сайт, вход, бонусы, верификация).
3. **Слоты (улики):** `mel_id` (AS_ids), `receipt` (PDF; скриншот — слабая улика), `wd_code` (4 символа).

### 2.1. Пачка (burst)

Решение принимается не по одному сообщению, а по пачке: все сообщения игрока за `grace_s` = 60 с от первого
(та же отсечка, что у Autosup для ID, D-AS-6). Досрочно — если тикет уже полон (D: ID + PDF; W: ID + код).
Каждое следующее сообщение до ответа пересчитывает пачку.

### 2.2. Признаки и веса

| Признак | D | W |
|---|---|---|
| PDF-документ (`application/pdf` или имя `*.pdf`) | **+4** | |
| Пересланное сообщение бота кассы о депозите: «Переведите точную сумму», «Заявка #… создана», «EPOS ID», «Реквизиты для оплаты», «Метод пополнения», «[ДЕПОЗИТ]», «Депозит №… принят/отклонён» | **+4** | |
| Код вывода (§3) | | **+4** |
| Пересланное сообщение бота о выводе: «Вывод с аккаунта», «Вывод на сумму … взят в работу», «Ваша заявка отправлена на модерацию», «Метод вывода», «[ВЫВОД]», «Введите сумму вывода» | | **+4** |
| Сильные слова: `пополн, депоз, деп, чек, квитанц, зачисл` | +3 | |
| Сильные слова: `вывод, вывел, вывест, снял, сняти, выплат, финализ, код вывода` | | +3 |
| Слабые слова: `перевёл, оплатил, скинул, закинул, завис, платёж, реквизит, на баланс, на счёт` | +1 | |
| Слабые слова: `на карту … не, придут на карту, модерац, отказ, одобр, сутки, частями, не весь, пришло только` | | +1 |
| Скриншот (фото) | +1 | |

**Тема:** `D`, если D ≥ 3 и D > W; `W`, если W ≥ 3 и W > D; `?`, если оба > 0 или есть только слова проблемы
(«не пришли», «где деньги», «сколько ждать», «завис»); иначе — нет темы.

**Намерение** (в порядке проверки):
1. есть PDF / код / пересланная заявка → `PROBLEM`;
2. `HOWTO`-слова (`как вывести/пополнить`, `можно ли`, `есть реквизиты`, `какой город/касса`, `не могу найти`) и нет слов проблемы → `HOWTO`;
3. слова проблемы (`не пришл/не поступ/не дошл/не зачисл`, `где деньги`, `завис`, `долго`, `сколько ждать`, `когда придут`, `сутки`, `N часов/дней прошло`, `проверьте`, `статус`, `частями`, `отклон`) или ID, или скриншот → `PROBLEM`;
4. `FOLLOWUP`-слова (`актуально`, `ещё не`, `новости`, `что там`, `?`, `ау`, `жду`, `сколько можно`, `я уже писал`) → `FOLLOWUP`;
5. только приветствия/стикеры/«оператор» → `GREETING`; «сайт, зеркало, не могу зайти, верификация, бонус, промокод, бан» → `OTHER`; остальное → `UNCLEAR`.

Рассылки ботов («Касса RAMZ PAY снова принимает пополнения…») — игнорировать.

### 2.3. Качество на истории (прототип, 3 136 обращений)

| Решение | обращений | подтверждено перепиской |
|---|---|---|
| `PROBLEM/D` | 745 (23,8 %) | D 653 · W 4 · смешанное 17 · без метки 71 |
| `PROBLEM/W` | 338 (10,8 %) | W 251 · D 2 · смешанное 14 · без метки 71 |
| `PROBLEM?/D` (тема есть, проблема не названа) | 129 | D 65 · W 1 |
| `PROBLEM?/W` | 165 | W 100 · D 5 |
| `PROBLEM/?` | 236 (7,5 %) | D 68 · W 38 → нужен уточняющий вопрос |

Ошибка «депозит ↔ вывод» при уверенном решении — меньше 1 %. Главная потеря — не ошибки, а приветствия и невнятные
сообщения (≈ 31 %): для них уточняющий вопрос обязателен.

## 3. Распознавание кода вывода (`AS_codes.py`, будущий)

- Токен ровно из 4 символов `[A-Za-z0-9]`, не приклеен к другим буквам/цифрам, содержит хотя бы одну латинскую букву.
- Не код: стоп-слова (`EPOS, Cash, RAMZ, USER, 1WIN, Ozon, Test, call, play, apps, Fast, Bank, Team, GOLD, PayT…` — список в конфиге).
- Код принимается, если выполнено одно: в токене есть цифра или смешанный регистр; **или** сообщение короткое (≤ 4 слов);
  **или** рядом «код», «code», «Вывод с аккаунта».
- Регистр сохраняется как есть (`tfVQ` ≠ `TFVQ`).
- Несколько разных кодов в сообщении — это несколько выводов (`M9mp / U7RY`): тикет хранит список кодов.
- **SMS-код:** сообщение только из 4–7 цифр, когда ждём код вывода, — не код. Ответ: подсказка про код из заявки (§5).

## 4. Протоколы и состояния

### 4.1. Когда стартует

Autosup уже держит личный диалог (contact.first / contact.second). Тикеты — второй слой поверх него:
каждое входящее личное сообщение игрока, если нет активного тикета, открывает **пачку**; через 60 с (или досрочно)
классификатор выдаёт решение.

| Решение по пачке | Действие |
|---|---|
| `PROBLEM/D`, `PROBLEM?/D` | открыть **D-Ticket**, запросить недостающие слоты |
| `PROBLEM/W`, `PROBLEM?/W` | открыть **WW-Ticket**, запросить недостающие слоты |
| `PROBLEM/?`, `DW?` | **уточнить тему** (вопрос «депозит или вывод?») |
| `GREETING`, `UNCLEAR`, `ID_ONLY`, `IMAGE_ONLY` | **уточнить вопрос** (общий шаблон «по депозиту — ID и чек, по выводу — ID и код») |
| `FOLLOWUP` + открытый тикет за 3 дня | прикрепить к тикету, ничего не писать (оператор видит) |
| `FOLLOWUP` без тикета | как `UNCLEAR` |
| `HOWTO/*`, `OTHER` | тикет не открывать, оставить оператору (позже — справочные ответы) |

### 4.2. Слоты

| | обязательные | заполняются из |
|---|---|---|
| D-Ticket | `mel_id`, `receipt_pdf` | AS_ids; PDF-документ; пересланная заявка бота («Номер аккаунта: …» → ID) |
| WW-Ticket | `mel_id`, `wd_code[]` | AS_ids; §3; «Вывод с аккаунта N CODE» → оба слота сразу |

`mel_id`: если у пользователя в RM ровно один MelID (`rm_player_mel`) — подставить и **не спрашивать**
(в истории так у 75 D и 73 W обращений без ID). Если MelID несколько — спросить.
Скриншот вместо PDF в D-Ticket: записать как `receipt_image`, один раз попросить PDF; если PDF так и не пришёл —
тикет всё равно уходит оператору с пометкой «чек — скриншот».

### 4.3. Состояния тикета (`as_tickets`)

```
burst ──(60 с / полон)──► classify
  ├─ D/W ───────────► collecting ──(все слоты)──► ready ──► handed (оператору)
  │                       │ 1-е напоминание через remind_s (15 мин), не больше одного
  │                       └─(ticket_ttl 24 ч без слотов)──► handed с пометкой «неполный»
  ├─ ?/GREETING ────► clarifying ──(ответ с темой/уликой)──► collecting
  │                       └─(второй невнятный ответ)──► handed («не классифицирован»)
  └─ HOWTO/OTHER ──► operator (тикета нет)
```

- Уточняем **не больше одного раза**; второй невнятный ответ — сразу оператору (так не зациклимся на азербайджанском/узбекском тексте и жалобах).
- Пока тикет `collecting`/`ready`/`handed` (до закрытия оператором или 3 дней), новые сообщения прикрепляются к нему:
  слоты дополняются, `FOLLOWUP` не плодит тикеты. Новая тема (был D, пришёл код вывода) — второй тикет.
- Любой исходящий ответ оператора в диалоге во время `burst`/`clarifying` — Autosup молчит (оператор перехватил).
- Состояние пишется в БД **до** отправки (инвариант 4); всё исходящее — через Outbox, `dedup_key` = тикет + шаг.

### 4.4. Связь с ID-протоколом (contact.first)

Сейчас первый контакт через 60 с получает «Здравствуйте! Пришлите ваш ID». Если в той же пачке определилась тема,
**отдельная просьба об ID не отправляется**: её заменяет одна общая просьба тикета (ID + чек / ID + код).
ID, пришедший в тикет, проходит обычную запись игрока (`_register`, закрепление).

## 5. Тексты (в конфиге; черновик)

| Ситуация | Текст |
|---|---|
| D, нет ID и чека | Здравствуйте! Пришлите, пожалуйста, ваш ID и чек об оплате в формате PDF 📄 |
| D, нет чека | Пришлите, пожалуйста, чек об оплате в формате PDF 📄 |
| D, есть только скриншот | Спасибо! Пришлите, пожалуйста, чек именно в формате PDF 📄 — его можно скачать в приложении банка |
| D/W, нет ID | Пришлите, пожалуйста, ваш ID |
| W, нет ID и кода | Здравствуйте! Пришлите, пожалуйста, ваш ID и код вывода 🔑 — 4 символа из заявки (раздел «Запросы на вывод» → «Получить код») |
| W, нет кода | Пришлите, пожалуйста, код вывода 🔑 — 4 символа из заявки (раздел «Запросы на вывод» → «Получить код») |
| W, прислан SMS-код | Это код из SMS, он не подходит. Нужен 4-символьный код вывода из латинских букв и цифр — раздел «Запросы на вывод» → «Получить код» |
| тема `?` | Здравствуйте! Уточните, пожалуйста: не поступило пополнение (депозит) или вывод? |
| приветствие / невнятно | Здравствуйте! 🟠 По депозиту — пришлите ваш ID и чек в формате PDF 📄 🟢 По выводу — ID и код вывода 🔑 Или напишите ваш вопрос |
| тикет полон | Спасибо, информацию получил и передал на проверку. Ответим, как только будет результат |

Ответ на «депозит или вывод?» распознаётся тем же классификатором (+ короткие ответы: «депозит», «деп»,
«пополнение», «1» → D; «вывод», «2» → W).
