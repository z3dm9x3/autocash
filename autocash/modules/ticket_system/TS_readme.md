# TS — Ticket System

Тикет-система: тикеты игроков между аккаунтами, процессы L1/L2. TS хранит данные и ведёт процессы, но
**сама ничего не пишет в Telegram**: факты она получает от других модулей, результаты передаёт им протоколами.
Решения: `docs/decisions.md`, D-TS-1…D-TS-5. Проект следующих шагов (сбор ID, чека и кода) — `TS_plan.md`.

## Кто что делает

| | AS (Autosup) | TS (Ticket System) |
|---|---|---|
| роль | общение с игроком: читает и пишет в конкретные чаты, записывает в базу | данные тикетов и процессы |
| Telegram | пишет (игроку, в `logs`) — через Outbox | не пишет |
| связь | передаёт в TS каждое личное сообщение игрока (`TS_api.receive`) | отдаёт результат протоколом `ticket.d` / `ticket.ww` / `ticket.q` |

Игрок — пользователь Role Manager (`rm_users`): контакты first/second регистрируют его там, своей таблицы
пользователей у TS нет. Сообщения персонала (casher, support, manager, admin, dev) и служебные сообщения
Telegram в TS не передаются.

## Тикет и C-ticket

- У игрока один открытый тикет. Первое личное сообщение его открывает, следующие добавляются к нему.
- **Только после запуска** (D-TS-4): сообщения backfill и сообщения, написанные до старта TS (догон после рестарта), тикетов не создают.
- **Пока тикеты не закрываются.** Финализация будет отдельной логикой; собранные тикеты потом будут очищены.
- **C-ticket** проверяет **каждое** сообщение в течение `burst_s` (60 с) от первого (D-TS-5):
  1. есть кандидат в код вывода (`TS_rules.code_candidates`) → поиск в базе кодов вывода (`TS_codes.find`);
     найден → сразу **WW** (`code`). **База пока заглушка: код никогда не найден.**
  2. иначе триггеры: только правила депозита → сразу **D**; только правила вывода → сразу **WW**;
     признаки D и W в одном сообщении → **Q** (`mixed`), однозначно;
  3. за 60 с ни кода из базы, ни триггера → **Q** (`none`): это ставит фон TS раз в 2 с.
- Тип ставится один раз. После этого признаки больше не ищутся (у следующих сообщений не пишутся ни правила, ни
  коды), тип не меняется. Дальнейшая работа с тикетом — другие протоколы.
- Предметное описание для людей: `knowledge/tickets.md` (C-ticket), `knowledge/withdrawals.md` (код вывода).
- Тип пишется в одной транзакции с протоколом `ticket.<тип>` (субъект — id тикета). Autosup по протоколу пишет
  запись в `logs`.

## Правила (`TS_rules.py`, `DEFAULT_RULES`)

Текст приводится к нижнему регистру, «ё» → «е»; выражения выполняются в re2.

**Депозит (D):**

| правило | срабатывает на |
|---|---|
| `d.popoln` | пополнил, пополнила, пополнение, пополнить, попалнил — любые окончания |
| `d.deposit` | депозит, депозита, дипозит, депазит (кроме «…вносили депозит» из инструкции бота по выводу) |
| `d.dep` | деп, депа, депу, депнул, депнуть, депал, задепал, дэп — целым словом (не «депутат», не «департамент») |
| `d.zakinul` | закинул, закинула, закидывал (кроме сообщений со словом «код») |
| `d.na_igru` | на игру, на игровой |
| `d.receipt` | чек, чека, чеки, квитанция |
| `d.paid` | оплатил, оплатила, оплачено |
| `d.sent` | перевёл, перевела, перевели |
| `d.payment` | платёж, платежа |
| `d.pdf` | документ PDF (`media_type = pdf`) |
| `d.bot` | пересланные сообщения бота кассы: «Переведите точную сумму», «Заявка #… создана», «EPOS ID», «Реквизиты для оплаты», «Метод пополнения», «Ожидание реквизитов», «…Время модерации может составлять до 30 минут» |

**Вывод (WW):**

| правило | срабатывает на |
|---|---|
| `w.vyvod` | вывод, вывел, вывести, выведу |
| `w.vyplata` | выплата, выплаты |
| `w.vyigrysh` | выигрыш, выигрыша |
| `w.karta` | карта, карту, карты, картой, карточка — целым словом (не «картинка») |
| `w.snyal` | снял, снять, снятие (кроме «снял видео/скрин», «с меня сняли») |
| `w.bot` | пересланные сообщения бота вывода: короткое «Ваша заявка отправлена на модерацию», «Введите название вашего банка» |
| `w.code` | код вывода, найденный в базе кодов (не правило текста: шаг 1 C-ticket) |

**Код вывода — кандидат:** отдельное слово ровно из 4 символов `A–Z a–z 0–9`, хотя бы одна латинская буква, без трёх
цифр подряд (`998p` — не код), не из списка исключений `code_exclusions` (`EPOS`, `Read`, `Cash`, `Fast`, `RWMG`,
английские и азербайджанские/узбекские слова…). Регистр сохраняется. Кандидаты каждого сообщения пишутся в
`ts_ticket_messages.codes`.

**Не триггеры:** «завис», «сутки», «деньги не пришли», «где деньги», «зачисление», «реквизиты», «24/48 часов» —
они бывают и у депозита, и у вывода.

Правила задаются в конфиге `modules.ticket_system.config.rules`: список `{name, kind: D|WW, pattern, media, unless}`.
Этот список **заменяет** все правила по умолчанию. Исключения кода — `modules.ticket_system.config.code_exclusions`
(тоже заменяет список по умолчанию).

## Проверка на истории

RAW личных сообщений Cash Monitor Dev (PG 5433), 15.08–19.11.2026: 3 136 обращений. Разметка — по ответам
операторов, не по словам-триггерам. Правила D-TS-5, база кодов — заглушка:

| тип | обращений | оператор вёл как депозит | как вывод |
|---|---|---|---|
| D | 979 (31,2 %) | 735 | 17 |
| WW | 530 (16,9 %) | 17 | 321 |
| Q mixed | 42 (1,3 %) | 14 | 6 |
| Q none | 1 585 (50,5 %) | 470 | 275 |

В 1 114 из 1 551 тикетов с триггером тип ставится по первому же сообщению. По сравнению с D-TS-2: код вывода
без слова вывода (около 77 обращений) пока не даёт WW — вернётся с базой кодов; «карта» рядом со словом
депозита даёт Q (−9 D).

## Запись в `logs` (пишет Autosup)

Одна запись на тикет — когда определён тип (D/WW — сразу, Q — через 60 с):

```
TS: тикет #123 — D · игрок 123456789 (@ник, MelID 1234567890) · аккаунт Dmitry · триггер: «пополнил»
TS: тикет #124 — Q · игрок 987654321 · аккаунт Dmitry · триггер: «пополнял», «вывести» — депозит и вывод в одном сообщении
TS: тикет #125 — Q · игрок 555555555 · аккаунт Dmitry · триггер: нет за первую минуту
```

Шаблон — `modules.autosup.config.ticket_log_text`. Ключ дедупликации «тикет + тип», поэтому повтор протокола
второй записи не даст.

## Таблицы (`TS_migrations/001_ts_tickets.sql`)

| таблица | что |
|---|---|
| `ts_tickets` | тикет: `tg_id`, `account_id`, `state` (пока всегда open), `ticket` (D/WW/Q, NULL до решения), `reason` (triggers/mixed/none), `trigger_rules[]`, `trigger_text`, `trigger_msg_id`, `messages`, `first_msg_id`, `opened_at`, `decide_by`, `classified_at`, `last_msg_at`. Открытый тикет у игрока один (уникальный индекс) |
| `ts_ticket_messages` | сообщения тикета и правила, сработавшие в каждом; без текста (он хранится в `messages` по своему сроку). Ключ `(account_id, msg_id)`, поэтому повтор сообщения ничего не меняет |

## Конфигурация

TS работает, только если в конфиге есть `modules.ticket_system`.

| ключ (`modules.ticket_system.config`) | по умолчанию |
|---|---|
| `burst_s` | 60 |
| `rules` | `TS_rules.DEFAULT_RULES` |
| `code_exclusions` | `TS_rules.DEFAULT_CODE_EXCLUSIONS` |

## Зависимости (явные)

- **Ядро:** протоколы (`autocash.core.protocols.emit`), `messages.media_type` (`pdf` для документов PDF, D-TS-3).
- **Autosup:** передаёт сообщения, пишет в `logs`.
