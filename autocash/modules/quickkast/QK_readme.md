# QK — QuickKast

Оператор пишет в личном диалоге аккаунта пула короткий триггер, и QuickKast заменяет его шаблоном: триггер удаляется, шаблон отправляется. Цель — минимальное время от триггера до шаблона (меньше 0,5 с).
Решения: `docs/decisions.md`, D-QK-1…D-QK-5. Перенесён из Cash Monitor Dev (`rucash_monitor/modules/quickkast`).

## Модуль-исключение (D-QK-1, D-QK-2)

QK не идёт обычным путём (буфер → PG → сортировщик → очередь → модуль → очередь Outbox → антифлуд), иначе это секунды.

1. Gateway вызывает `express()` модуля сразу, до буфера. Решение принимается только по памяти: исходящее сообщение аккаунта пула, набранное человеком (не наша отправка), в личном диалоге, целиком равно триггеру активного профиля.
2. Экспресс-полоса Outbox (`OBX_express.py`) одной транзакцией записывает две задачи (`qk.delete` и `qk.send`, приоритет 0, сразу в этапе `sending`) и тут же, параллельно, удаляет триггер и отправляет шаблон.
3. Антифлуд и лимитер QK не ждут: нет очереди, равномерного шага, интервала на чат и темпа. Записи QK учитываются в окне аккаунта, и обычные задачи аккаунта идут после них. Останавливает QK только пауза Telegram (FloodWait).
4. Времена каждого этапа пишутся в `qk_events` уже после ответа Telegram.

Сообщение с триггером при этом проходит и обычный путь и хранится, как любое сообщение.

Каталог общий с QuickCast2 (`autocash/modules/quickcast2`, D-QK2-3): `QK_catalog.shared` — один объект на базу; `/qk add`, `/qk set`, `x` / `v` действуют и на QK2.

## Триггеры в диалоге

| Оператор пишет | Что происходит |
|---|---|
| `ТРИГГЕР` | случайный вариант шаблона |
| `ТРИГГЕР-N` | вариант N |
| `ТРИГГЕР-list` | все варианты одним сообщением |
| `ТРИГГЕР-N`, где вариантов меньше N | «Для триггера … доступно только … вариант(а).» |
| `x` или `х` | QK выключен в этом диалоге этого аккаунта (триггер удаляется) |
| `v` | QK снова включён в диалоге |

- Триггер — всё сообщение целиком, с учётом регистра; пробелы по краям не важны.
- Не срабатывает на сообщения собеседника, группы, пересланные сообщения, медиа, «Избранное».
- Шаблон отправляется с разбором Telegram-markdown, как все сообщения Autocash.

**Неудача (D-QK-3).** Аккаунт на паузе (FloodWait) — ничего не удаляется и не отправляется. Ошибка Telegram — без повтора. Запись в журнал монитора и в `logs` (не чаще раза в 10 минут, со счётчиком): `QK: триггер «…» в диалоге … (аккаунт …) не отработал: <код>`.

## Команды

Только в группе с ролью tech, права — Admin и Dev. Без прав — в чате ничего, отказ в `logs`.

| Команда | Что делает |
|---|---|
| `/qk` | справка |
| `/qk on` / `/qk off` | включить / выключить QK (запись в `logs`) |
| `/qk add ТРИГГЕР ТЕКСТ` | добавить вариант в активный профиль; текст может быть многострочным |
| `/qk add ТРИГГЕР` ответом на сообщение | текст того сообщения становится вариантом |
| `/qk delete ТРИГГЕР` / `ТРИГГЕР-N` | удалить триггер / один вариант (остальные перенумеровываются) |
| `/qk list [ПРОФИЛЬ]` | шаблоны профиля |
| `/qk add profile ИМЯ` | создать профиль |
| `/qk set ИМЯ` / `/qk set` / `/qk profile clear` | выбрать профиль / вернуться в standard |
| `/qk profile list` | профили, активный отмечен • |
| `/qk stats` | за сутки: p50/p90/max от прихода триггера до ответа Telegram, по этапам |

Добавление шаблонов, профилей и смена профиля пишутся в `logs`.

## Обратная связь (AGENTS.md, правило 9)

В диалог QK пишет только шаблон (или список вариантов / «доступно только N»), и только в ответ на триггер оператора. Сам триггер удаляется.

## Конфигурация (`modules.quickkast.config`)

| Ключ | По умолчанию | Что |
|---|---|---|
| `ttl_s` | 30 | срок задач QK: не отправлено за это время — не отправляется |

## Таблицы (`QK_migrations/001_qk.sql`)

- `qk_settings` — включён ли QK, активный профиль;
- `qk_profiles` — профили (имя без учёта регистра уникально);
- `qk_templates` — `profile`, `trigger`, `variant`, `template`;
- `qk_chat_state` — выключенные `x` диалоги (`account_id`, `chat_id`);
- `qk_events` — каждое срабатывание: `received_at` (апдейт пришёл в Gateway), `matched_at`, `stored_at` (задачи в PG), `deleted_at`, `sent_at` (ответ Telegram), задачи Outbox, `status` (done / partial / refused / failed), `reason`.
